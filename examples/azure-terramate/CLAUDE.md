## Standard Variable Set

These variables appear across all modules:
- `prefix` — Resource name prefix (e.g., `app-weu-dev`)
- `location` — Azure region (default: `westeurope`)
- `resource_group_name` — Target resource group
- `tags` — Additional tags (`map(string)`)
- `env_default_tags` — Default tags from Terramate globals
- `subscription_id`, `tenant_id` — Azure identifiers

## Naming Convention

`{prefix}-{resource_abbreviation}-{suffix}`
- Key Vault: `{prefix}-kv-{suffix}` (max 24 chars, truncated with `substr`)
- Private Endpoints: `{prefix}-pe-{suffix}`
- Names sanitized: `regexreplace(var.suffix, "[^0-9A-Za-z]+", "-")`
- Optional `full_name` override on most modules

## Tagging Standard

```hcl
local.tags = merge(var.env_default_tags, var.tags)
```
Required tags: `environment`, `product`, `managed_by = "Terraform"`.

## Terramate Hierarchy

```
infrastructure-config/
  globals.tm.hcl                        ← org-wide defaults
  _generate/                            ← shared generate_hcl blocks (backend, provider)
  {environment}/
    globals.tm.hcl                      ← env: name, location, subscription_id
    {stack}/
      globals.tm.hcl                    ← stack: prefix, service name
      stack.tm.hcl                      ← stack identity and ordering
      {component}.tf                    ← hand-written module call
      _generated_backend.tf             ← generated by Terramate (do not edit)
      _generated_provider.tf            ← generated by Terramate (do not edit)
```

### Input flow
```
Root globals.tm.hcl → Environment globals.tm.hcl → Stack globals.tm.hcl
```
Each level extends the previous. Values are referenced as `global.{key}` in generate_hcl and stack configs.

## Coding Standards

### Terraform Files (`tf-module-*/**/*.tf`)

**File organization:**
- `main.tf` — provider requirements + data sources
- `{resource}.tf` — core resources, named by Azure resource type
- `locals.tf` — name construction, tag merging, computed values
- `variables.tf` — module-specific variables
- `common.variables.tf` — standard cross-module variables
- `outputs.tf` — module outputs (at minimum: `name` and `id`)
- `versions.tf` — terraform and provider version constraints

**Resource conventions:**
- Single resources use identifier `"default"` (e.g., `azurerm_key_vault.default`)
- Map-driven resources use `for_each` with descriptive keys
- Boolean toggles use `count`
- Tags: `merge(var.env_default_tags, var.tags)` — always

**Provider versions:**
```hcl
azurerm = { source = "hashicorp/azurerm", version = ">=4.21.0,<5.0" }
```

### Terramate Files (`infrastructure-config/**/*.tm.hcl`)

**`stack.tm.hcl` pattern:**
```hcl
stack {
  name        = "{service}-{environment}"
  description = "Manages {description} in {environment}"
  id          = "{service}-{environment}-weu"
  after       = ["../networking"]  # explicit ordering
}
```

**`globals.tm.hcl` pattern:**
```hcl
globals {
  environment = "dev"
  prefix      = "app-weu-dev"
}
```

**`generate_hcl` (in `_generate/`):**
- Generates `_generated_backend.tf` and `_generated_provider.tf` per stack
- Never edit generated `_generated_*.tf` files
- Run `terramate generate` after changing any `generate_hcl` block

### Test Files (`**/*.tftest.hcl`)

```hcl
mock_provider "azurerm" {}

override_data {
  target = data.azurerm_subscription.current
  values = { tenant_id = "00000000-0000-0000-0000-000000000000" }
}
```

- All tests: `command = plan` — never `command = apply`
- Include all `common.variables.tf` variables in `variables {}` block
- One test file per concern: `naming.tftest.hcl`, `tags.tftest.hcl`, etc.

### Pipelines

Two-stage: Plan → Apply (on protected branches with approval). Identity-based auth (MSI). Provider caching.

## Behavioral Rules

- DO NOT run `terraform apply` or `terraform destroy` without explicit approval
- DO NOT run `terramate run terraform apply` without explicit approval
- DO NOT hardcode secrets, account IDs, or credentials
- DO NOT edit `_generated_*.tf` files — always edit `generate_hcl` source and regenerate
- DO NOT change `common.variables.tf` unless the variable is genuinely cross-module
- ALWAYS run `terramate generate` after changing `generate_hcl` blocks
- ALWAYS verify `terramate generate` produces no unexpected diff before committing
- ONLY use `command = plan` in tests

## Principles

1. **Minimal intervention** — smallest change that fulfills the requirement
2. **DRY** — shared config in `generate_hcl` and globals, values flow from hierarchy
3. **No hardcoded secrets** — use Key Vault, MSI, or Terramate globals
4. **Plan-only tests** — mock providers, no real resources
5. **Never edit generated files** — edit source and regenerate
